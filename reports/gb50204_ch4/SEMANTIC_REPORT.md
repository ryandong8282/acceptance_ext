## 关键裁决

1. **单纯集成通用组件并不会自动超过 PDFex。** v0.1 的行级解析能看到部分条文，但不能把下一行的“检查数量/检验方法”归属于上一条，也不会展开 HTML 合并单元格表，因此表格项和抽样语义几乎全部丢失。
2. **v0.2 变强不是因为多装了几个库，而是补回了领域编译器。** 它建立条文边界、主控/一般项目状态、表格行语义、抽样 DSL、证据绑定和 GB 50300 节点挂载；这些正是 PDFex 数月工作的核心。
3. **本轮发现并修复了一个真实语义缺陷。** 旧集成结果在 4.2.9、4.2.10 的机器脚本里只保留“大空间结构的板”，漏了“大空间结构的墙按相邻轴线间高度约 5m 划分检查面”的分支。自然语言 `min_sampling` 没漏，但机器规则漏了；v0.2 已拆成墙、板两个独立分支。
4. **当前还不能宣判 v0.2 胜过 Acceptance Pi。** 必须给比较器一份 Acceptance Pi 对同一 Markdown 的实际 JSON。没有候选结果就没有可审计的 head-to-head，不能用架构印象代替成绩。
